- Candidate SQL and transport are test-only and must never be imported by active application code or placed in migration history, because only disposable preparation is authorized.
- All database writes use a newly created loopback-only PostgreSQL cluster with inherited PG variables removed, because the real project database is shared with production.
- Historical corrections append separate events; source results, answers and native QRC stay immutable, because preparation must never rewrite learner evidence.
- Historical grading candidates must retain divergent native links, quarantine every pre-existing correction trace, match the original submission instant and lock its source row; why: matching IDs or a numeric placeholder alone cannot authorize a duplicate correction.
- EB2 consultation projection keeps original result/question identities and exact same-attempt submission evidence; it exposes no grading capability and remains test-only, because displaying historical answers must not authorize writes or claim unproven submission.
