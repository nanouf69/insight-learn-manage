# Correction QRC V2
- Custom quick comments use a shared admin-only server catalog, version CAS and archival removal; their text is copied locally into the existing explicit correction save, never linked dynamically to learner history; why: editing the shared list must never rewrite feedback or grades.
- Admin revision answers read persisted account-scoped rows, require explicit sourceResultIds matching owner/exam/subject and frozen question before displaying initial answers/attempts, and only attach journal times matching persisted values; why: events and revision round numbers cannot prove copy identity.
- Historical-only copies use CopiesHistoriquesLecture without grading controls, never CorrectionQRCTab; why: missing frozen barèmes and automatic keyword marks must not become human corrections.
- All subject grids and copy navigation use ordonnerCandidatsParFin after gathering their passages; completed passages use recorded finish instants descending, with immutable IDs for ties; why: server discovery order and correction timestamps must not override per-subject finishing order.
- EB2 VTC copies without a V2 QRC record appear in the same V2 grid via eb2Consultation (ids `consultation:<result_id>`) and are graded only through RPC `qrc_historique_noter` (locks the original result, proves stored score = exact QCM + recorded points, refuses validated QRC/V2-linked copies, append-only journal); UI submits automatically only for proven matching owner/exercise/attempt/answers and never manufactures human recognition for unmatched copies; why: removing the checkbox must not bypass server identity checks or rewrite grades.
- Grading RPC refusals never use SQLSTATE 40001/40P01; why: the API layer retries those automatically and loops while holding the row lock.
- Historical submission linkage compares the complete immutable answer-key set and exact QRC text; only frozen QCM letter arrays may differ by permutation, with duplicate/unknown letters refused, and copy provenance is reread before grading; why: checkbox order falsely rejected authentic submissions, but text normalisation or manual recognition cannot prove identity.
- A historical copy whose only submission carries the attempt in its exercise key (`__tN`) while the legacy tentative column kept its default 1 is gradable only through an append-only row of `qrc_historique_liaisons_remise`, re-verified live (fingerprints, uniqueness, same learner) by `qrc_historique_liaison_prouvee`; first grading of a `resultat_seul` copy is refused even with a typed recognition; why: the suffix is the attempt identity for those rows, but tolerating the mismatch globally or by admin confirmation would not prove identity.
- Consultation passage and submission reads use deterministic primary-key pagination, including all enrollment-proof pages; why: a valid submission beyond the first 1000 records must not disappear from the displayed copy.
- QRC auto-grading (proposerPrenote) fires only for literal identity after conservative normalisation that keeps signs, digits, units, currency, % and negations; any other proposal is a preselection and a grade click saves immediately (admin request 10/11); why: stripping symbols graded « −10 euros » as « 10 euros » and clicks saved unintended grades.
- The grid lists every finished EB copy once: V2 attempts, EB2 VTC consultation, and every other non-migrated historical copy with a written QRC as « ancien circuit »; historical copies are hidden only when migrated (source_historique) or proven V2 mirrors (same learner/exam/subject, single finished native attempt, identical QRC texts). PanneauRapprochement recounts expected vs visible copies from the server and lists any missing copy by name; why: evening/TAXI candidates disappeared silently through partial reads.
- Learner/session lookups in listerGroupesCrm are chunked (150 ids) and read errors throw; why: oversized `.in()` URLs failed silently and pushed candidates out of their CRM session.
- `trg_qrc_v2_bareme` refuses a V2 QRC note < 0 or above the restored/frozen barème (P0478, unknown barème = only the 0 bound); why: the UI buttons were the only bound.

- Comment-only changes on an already graded QRC go through `core_commenter_qrc` (V2) or `qrc_historique_commenter` (legacy), append-only with CAS on note + last event/revision and operation idempotence; candidates read the latest via commentaireQrcPersistant / `qrc_historique_commentaires_eleve`; why: same-note revisions never journal a comment and grades must never change to carry feedback.
