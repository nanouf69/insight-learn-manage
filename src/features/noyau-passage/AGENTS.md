- V2 exam answer queue (pontV2) keeps one pending value per attempt/subject/question (latest by timestamp wins, in-flight never removed), sends one request at a time for the whole browser (Web Locks, 20 s call cap) and backs off per attempt (1 s→30 s max incl. jitter) except explicit finish/online; every mutation re-reads shared storage with per-item uids, falls back localStorage→sessionStorage→memory and exposes that state so the UI warns, guards unload and never shows "saved" before server confirmation; why: per-keystroke writes/retries overloaded the database on 12/11, and blind whole-queue writes let one tab or a refused storage silently drop answers.
