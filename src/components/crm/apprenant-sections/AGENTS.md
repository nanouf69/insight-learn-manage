# Subject-reset boundary
- Whole-exam reset cancellation is a disabled preview until effective cutoff, exclusive neutralisation and authorization projections cover every reader and starter; use exact reset identity and never write results or originals. Why: a cancellation event alone cannot restore consistent access or grades.
- CRM Examen blanc averages project the selected result through attacherSourceUnique and refresh on useCoreChangeTick; selection remains latest recorded tentative, never latest correction date. Why: correcting an archived copy must not replace a later copy, and legacy pending totals must not hide definitive V2 grades.
- CRM subject-copy history reads each source result by its immutable ID, never latest-attempt merging; correction links require matching owner/exam/source ID/attempt and byte-identical saved details, then the existing QRC/group IDs. Why: a partial later copy must not hide or replace a complete earlier copy.
- Per-subject reset reads the server-owned source/version (`exam_subject_reset_context`), verifies displayed learner/result identity, then requests a dedicated append-only admin authorization with readback; the learner alone starts the new tentative (owner-only deferred start). Open copies and unproven old/V2 links are refused, never replaced; no global or owner-start fallback; why: admin must never start timers, alter other subjects or rewrite grades. Server changes must pass `src/test/admin_subject_reset_sql_contract.py` and `src/test/admin_subject_reset_live_contract.py` (live triggers on a disposable cluster).
