# Persistence boundaries
- Attendance PDF signature cells reserve a separate bottom band for the exact row learner identity through nomSousSignature; never infer or replace signature evidence. Why: names identify signed and unsigned cells without covering handwriting.
- Attendance-addition notes use the optional bounded motifPresence schema; cancellation reasons and frozen-practice statement requirements remain separate. Why: optional free text must not bypass protected evidence workflows.
- Missing-signature PDFs share the recorded-range minute parser and union same-date intervals for totals, preserve handwriting space and remain unsigned worksheets. Why: duplicate enrollment and overlap must never manufacture attendance hours.
- Manual attendance cancellation uses the append-only `presentiel_decider_validation` journal (CAS, original snapshot, readback); slot validation uses `presentiel_valider_creneau` (private admin PDF in `presentiel-justificatifs`, exact enrolled unsigned slot, day total ≤ planned, explicit replacement of date-only rows) and writes a normal validation plus an immutable slot link; all live readers share lirePresencesAdministratives, frozen archives stay separate; SQL changes must pass `src/test/presence_lot_operationnel_sql_contract.py`. Why: originals survive reversible withdrawal and no hour is counted twice.
- Unsigned-hour counters sum exact recorded ranges of missing slots, independently of date-only admin declarations; unknown/conflicting ranges remain unquantified. Why: presence evidence never substitutes for a missing signature.
- Live initial VTC presential totals share chargerTauxPresenceHeures and pratiquePrevueVtc across CRM, learner and dashboard; VTC-only target deduplication, supplementary practice reads and obligation require both track and dossier eligibility. Why: this lot must not alter configured TAXI/TA/VA programs, FC or frozen evidence.
- Formation invitation HTML uses an explicit continuing-training projection and removes only identified legacy paragraphs locally; why: keep saved templates, access rights and sent mail history unchanged while avoiding duplicate summaries and initial-exam instructions in FC.
- First-passage rates retain their exact counted/excluded observations in the same read model; drilldowns never reread approximate copies, QCM needs submitted native proof, and full-copy mirrors use shared strict provenance. Why: detail denominators and frozen answers must match the displayed statistic.
- Effective reset read adapters remain disconnected until all readers and refresh paths are approved; why: a passing isolated projection cannot establish coherent production displays.
- Previous EB summaries resolve each older result through its exact official publication evidence and label single/partial subject coverage; admin copy-selection previews never persist or override latest-tentative defaults. Why: legacy pending grades and correction dates must not masquerade as historical exam averages.
- FC paper attendance remains separate immutable document-linked admin evidence per inscription/date/slot; live missing-slot reads merge it without synthetic images, original timestamps or frozen milestone changes.
- EB first-passage QRC statistics use the submitted qrc_instances_v2 copy and frozen points, with human correction priority or an exactly matching applied AI receipt; full marks = success, pending/retakes stay unproven, never grade the first keystroke; why: typing events are not submitted answers and unvalidated corrections cannot invent failure rates.
- Equipment custom quiz transport always sends a null SQL score and confirms only identical account-scoped version/revision/answers readback; why: these guarded activities are non-graded and old rejected operations must not cancel a proven submission.
- Optional TAXI quiz drafts use account/quiz/attempt-scoped pending journals, serialized per-answer RPCs and same-account readback; conflicts preserve both versions, submitted answers use server proof only; why: device races and offline retries cannot falsely validate or erase drafts.
- Editor save acknowledgements apply only to their local edit revision; unfinished currency-only choices remain local and explicit saves cancel pending draft timers; why: older asynchronous replies must never publish a missing amount or erase a newer input.
- Activity display separates confirmed performance from required/optional status via statutActiviteEleve; why: waived or collapsed quizzes must remain visibly unperformed without changing milestone requirements.
- Dashboard pending EDOF practice uses the shared signature classifier and latest EDOF badge query, display-only; why: signed practical dates disappear on confirmed E marking without deleting proofs or counting theory.
- Attendance windows are server-owned; consumers use `emargementFenetres` for due slots, actual hours and next-opening delay; why: theory, practice and manual signatures must share exactly the same authorization.
- Technical RPCs use freshSessionCall with same-account checks; module pages use an account-scoped durable queue and server readback; why: no anonymous calls or false confirmations.
- Revision queue successors reuse a confirmed write sequence only when their full revision state preserves the preceding payload without conflicts; skipped server versions may be retried under a new operation ID only as strict supersets of both server and queued answers, otherwise they remain blocked; why: fast typing cannot stall closure or overwrite another tab/device.
- Upload client shares documentUploadRules and stable operation IDs across retries; why: limits and acknowledgements must match the server.
- Trailing-dot correction opens a new tab manually without transferring auth/storage; why: separate browser origins must retain their own queues.
- Autosave pending drafts have a separate account/dossier-scoped journal from confirmed caches; why: an older in-flight acknowledgement cannot erase newer local edits.
- moduleAccessDerogation intersects admin-written access grants with the learner's assigned modules and separates never-submitted exam subjects from finished copies; why: access must not create completion, replay submitted work, or transfer permissions between accounts.
- Live content refresh goes through `createLiveRefresher` (src/lib/moduleLiveRefresh.ts): version probe, full reread on change or every 2 min, single-flight, jittered Realtime, bounded backoff; quiz rereads use `relireAvecReprisesBornees` (transient errors only); why: 5 s full rereads saturated the DB pool.
- Every visitor (learners included) gets a stale-tab check (deployedVersionWatch: no-store reread of published index on focus/visibility/5 min) that only shows the existing manual « Recharger » notice; the learner module subtree must not depend on parent callback identity; why: a fix published while a tab stays open never reached the learner, and auto-reload could lose input.
- Activités définies dans le code (jeux de Lyon, module 8 VTC/VA) : registre unique `src/lib/jeuxPedagogiques.ts` (ACTIVITES_CODE) lu par l'affichage, les volumes et les jalons live ; fin = réalisation confirmée serveur (`reponses_apprenants`, score null) ; calculs figés non modifiés ; why: tout ajout se reflète dans les jalons sans liste parallèle.
- Bilans d'exercices = projection des sources serveur actives des modules 2/10 via BILAN_SOMME_COURS_SOURCES : ajouts, modifications, ordre et suppressions explicites suivis après chaque lecture/reconnexion ; contenu actif pris de la source, IDs historiques et JSON brut préservés, version serveur rétablie avant sauvegarde, bilans d'examen/EB exclus ; why: aucune question supprimée ne réapparaît et aucune copie ou preuve élève n'est réécrite.
- TAXI 2026 module 6 dispensation: a module completed before `BORNE_DISPENSE_TAXI_2026` (server time of the 23/10 request) keeps its result without the 3 activities, via `exigeeSiValideApres` shared by learner view and milestones; later completions require them; why: "except those who finished" without a permanent waiver.
- Additive code-defined course+quiz activities (e.g. module 64 Équipements TAXI complementary questions) use the registry with `horsVolumeSiValideAvant`, their own immutable ID/version and a DB guard trigger; modules validated before the borne exclude them from requirements AND volume; why: new content never changes finished learners' milestones, status or durations.
- Module 10 Réglementation supports (course IDs 10014–10018) and module 64 course 64001 are replaced at display time only via `projeterSupportTaxi` (versioned PPTX + faithful PDF assets); TA, VTC, module 24 and other courses keep their files; why: replace TAXI supports without touching page identities, saved data or other tracks.
- Module 64 Équipements TAXI missing from an explicit TAXI/TA theory list (contains 10 or 40) is added at display time at the END of the list and always unlocked, never written to `modules_autorises`; `modulesExigesDashboard` drops it from counters/jalons when the parcours was completed or access ended before the borne; why: give access without regressing finished learners or locking later modules.
- Module 7 additive communes panels are routed by the existing commune exercise IDs via module7ActivitiesDisplay, never by module ID alone; why: unrelated selected quizzes must not be obscured by a shared activities dashboard.
- Verified local optional-quiz keys live in correctionsLocalesVerifiees with exact ID/text guards, never in the copied TA bank; why: targeted feedback fixes preserve shared content and stored answers.
- Native V2 QRC subjects whose legacy row only holds a truncated question summary (same ids/order/statements, no choices/expected answer) use the definitive V2 note when answers match (contenuFicheTronqueCompatible); QCM-only subjects keep the strict choice proof; why: legacy copies never carry server QRC corrections and stayed "en attente" forever.
- Module completion saves: identical in-flight payloads are shared (single-flight) and retries use jittered backoff; server progress merge (fusion_details_progression) must stay linear and pass the 980-case equivalence replay; why: quadratic merge and synchronized retries caused 57014 under load.
- U+0000 answers: the device sends the exact text; only lots containing U+0000 go through persist_answer_batch_v3, storing a NUL-free projection plus a versioned per-question original (originauxExacts, valid only when projection and write seq match); readers needing exact text use lireReponsesExactes, never decode unmarked/unknown versions; the old U+2400 codec stays unused; why: lossless without touching literal symbols or existing rows.
- EB result screens: a copied V2 passage (snapshot result_id = row id) inherits the V2 note only when definitive and its frozen historical details are identical to the row (fichesIdentiques); learner card and CRM Résultats share lignesExamenAffichees and the same verdict states; why: old summaries never pass content checks and stayed pending, and the admin tab mixed attempts and showed red for undetermined verdicts.
- Paged reads (range) in coreExamPublication/passagesV2NonFiables always order by primary key; why: unordered pages over 1000 rows dropped/duplicated rows and made corrected copies flicker to pending.
- « Refaire les questions fausses » matches a frozen QCM to the current one only by unique stable ID, same type, and per-letter texts equal after deterministic cosmetic canonicalisation (whitespace, exact whole-text repetition); only the key may differ. No official choice-continuity mapping exists for EB, so rewrites, swaps or letter changes keep the frozen question/key; why: identical letters or a single changed field do not prove a choice kept its meaning.
