## Cause et correction

- Le serveur journalise les clics même quand `base_seq` est ancien et que la copie les ignore. Les traces montrent notamment le deuxième choix ajouté à un QCM multiple journalisé après la valeur seule restée en copie.
- Abdelhak a encore journalisé ses choix à 18:53 le 13/11, avant le correctif 19:26 ; Alpha et Malki ont leurs derniers écarts le 12/11. Le correctif Edge ne répare pas rétroactivement les copies sans nouvel envoi.
- Cabral a une copie concordante actualisée à 19:35. Son état `in_progress` seul ne prouve pas une intention de remise ; son journal ne contient pas de preuve du clic Valider. Le navigateur existant refuse avant relecture lorsque `flushAnswerSavesAndWait` échoue : c'est la barrière corrigée dans le flux isolé, pas une preuve que sa tablette détenait précisément le lot fictif testé.
- Le RPC existant `submit_quiz_attempt` remplace les réponses sans CAS. L'appeler directement après une lecture pourrait écraser une écriture arrivée entre les deux. D'où un wrapper ciblé, pas une modification de ce RPC pour tous les élèves.
